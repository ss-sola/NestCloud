# 配置发布与客户端协作

## 草稿和版本

管理页的“保存”写入草稿，“保存并发布”先保存草稿，再使用返回的草稿 ID 发布。编辑已发布快照时，服务会创建或复用同名草稿。版本号、MD5 和发布时间由服务端维护，旧快照继续可供历史查询。正文变更会重新计算 MD5。

草稿保存与发布在 PostgreSQL 可串行化事务内读取和写入。两个请求发生序列化冲突时，其中一个收到 HTTP 409，可在刷新草稿后重试。重复发布同一已发布记录返回原快照。

## 发布校验

草稿可保存未完成的正文。发布时，JSON 与 YAML（含 YML）必须能解析为可通过 JSON 返回的对象，数组、标量、空文档和循环引用均会被拒绝。ENV 和 properties 使用 dotenv 赋值语法，支持空行、注释、空值和多行引号值；未识别的赋值行会被拒绝。校验失败返回 HTTP 400，草稿和上一已发布版本均可继续使用。

## 客户端拉取

客户端按指定文件名的顺序叠加已发布配置，后一个文件覆盖同名配置键，对象递归合并。拉取时使用发布校验的解析器。对于升级前已经发布的错误配置，同名文件回退到最近可解析的已发布版本，响应内的版本号、摘要和正文均来自该快照。若该文件所有已发布版本都无法解析，整次拉取返回 HTTP 422，客户端可保留当前有效配置。

## JSONC 配置

服务配置文件使用 `<ServiceName>.jsonc`。根节点是对象，可以使用 `//` 行注释或 `/* … */` 块注释。编辑器格式化保留注释，发布时校验语法。查看和版本历史保留原文，客户端的 `mergedConfig` 仅包含解析后的配置值。
