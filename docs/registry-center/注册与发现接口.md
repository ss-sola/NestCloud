# 注册与发现接口

## 注册实例

`POST /api/registry/register` 接收 JSON 对象。

| 字段                | 约束                        | 含义                                     |
| ------------------- | --------------------------- | ---------------------------------------- |
| `id`、`name`        | 必填，非空字符串            | 实例 ID 与服务名                         |
| `baseUrl`           | 可选，完整 HTTP(S) URL      | 对外服务地址，含路径前缀，可使用显式端口 |
| `host`、`port`      | 省略 `baseUrl` 时两者均必填 | 实例主机和端口，端口范围为 1 至 65535    |
| `group`、`metadata` | 可选                        | 实例分组及附加信息                       |

例如，`{"id":"middleware-1","name":"middleware-service","baseUrl":"https://middleware.example.com/api"}` 会保存完整地址，并补齐 `host=middleware.example.com`、`port=443`。若同时提供独立的 `host` 和 `port`，会保留这两个值供旧客户端读取。

使用旧协议的实例仍可发送 `{"id":"middleware-1","name":"middleware-service","host":"10.0.0.7","port":3300}`。心跳时间由注册中心生成。基础地址只接受协议、主机、可选端口和路径，参数校验失败返回 HTTP 400。

## 读取实例

`GET /api/registry/discover/{serviceName}` 按服务名返回实例，可通过 `group` 过滤。`GET /api/registry/all` 按服务名返回实例清单。两者均沿用原有响应结构，包含注册时传入的 `baseUrl`。新消费端优先使用该字段，旧记录继续通过 `http://host:port` 访问。
