# 存储策略与协作约束

## 存储策略

当前实现支持两种后端：

- Redis 存储
- 内存存储

是否启用 Redis 由配置决定；未配置时回落到内存模式。

## 续约和过期清理

Redis 中的实例哈希沿用 JSON 记录和原有键前缀。读取旧租约时移除客户端曾上报的 `heartbeatInterval`，下次成功续约时写回新的记录。清理任务默认每 30 秒扫描一次，超过 180 秒未续约的记录进入待清理集合。Redis 脚本在实例哈希内比对扫描时读到的完整记录，匹配后才删除。续约也在同一哈希内比对旧记录并更新时间。两个脚本都只访问一个键，原有 Redis Cluster 键可以位于不同哈希槽。

如果实例已续约或重新注册，清理会跳过旧记录。若清理先完成，迟到的心跳返回 `success: false`，客户端重新注册。只有成功删除记录的清理任务才更新过期计数和审计。指标、审计和服务名称索引在租约变更后分别写入，进程在此期间中断可能留下不完整的统计或索引。

按名称发现服务时，注册中心从权威实例哈希筛选服务名及分组。兼容旧版本的服务名称集合在每次改动后会复查当前实例；清理期间同一 ID 重新注册时，会根据最新所属服务修正集合。Redis 账号需要原有数据命令及 `EVAL` 权限。

手动摘除状态保存在实例租约中。Redis 的注册、续约和手动摘除或恢复都比对旧快照后写入，避免并发的注册或续约覆盖流量开关。发现接口和服务名称集合只包含接收流量的实例，管理页仍能查看已摘除的实例。

## 协作约束

- 对外接口或存储策略变化时，需要同步更新：
  - `docs/project/配置中心与注册中心.md`
  - `docs/project/部署与可观测性.md`
- 业务服务的远程调用与发现逻辑不应绕过这里的统一能力
