# 服务监控

NestCloud 控制台按实例展示进程 CPU、常驻内存（RSS）、堆内存和采集时间。CPU 以一个逻辑 CPU 满载为 100%。

逻辑核心数、系统内存占用和磁盘容量取自各实例所在的运行环境。系统内存显示已用量及占比，进程 RSS 单独显示。磁盘总量和已用量对应服务工作目录所在文件系统。使用旧版 SDK 的实例会显示空值，其进程指标仍可查看。页面可按服务筛选、点击列名排序，并设置每页显示的实例数。自动刷新保留筛选和排序，页码超出范围时回到最后一页。

页首汇总全部服务和实例的采集状态。表格以状态标签显示实例状态，并用进度条辅助比较进程 CPU、系统内存和磁盘占用。进程 CPU 超过 100% 时继续显示实际数值。

「持续高占用」按实例去重统计。进程 CPU ≥ 80%、系统内存占用 ≥ 85% 或磁盘占用 ≥ 85%，任一项持续至少 60 秒，服务名和对应指标标红。三个资源独立计时。单项回落、采集失败、进程重启或采集间隔超出两个周期时重新计时；过期快照退出统计。

## 接入和配置

1. 升级被监控服务使用的 NestCloud SDK，在 NestCloud 和各服务的本地部署配置中填写相同的 `ServiceMonitorToken`。NestCloud 还需填写现有的 `ControlPlaneToken`，以保护汇总接口。
2. 在 `ServiceMonitorTrustedHosts` 指定允许采集的注册实例主机名、IP 或 CIDR。采集访问实例的监听端口及固定路径 `/_internal/process-metrics`。域名须由可信的服务网络解析。
3. 通过 `ServiceMonitorStaticTargets` 添加未注册的网关、开发实例或控制面自身，例如 `gateway-service=http://gateway:3100,config-service=http://nestcloud:3001`。固定目标应是采集器可直接访问的实例地址。
4. `ServiceMonitorIntervalMs` 默认 10000，允许 5000 至 300000 毫秒。修改部署配置后重启 NestCloud。

## API

`GET /api/registry/monitor` 返回采集状态、实例 `list`、`highUsageCount` 和阈值 `highUsagePolicy`。持续超限的实例包含 `highUsage`，列出达标的资源（`cpu`、`memory`、`disk`）。控制台复用控制面会话，刷新按钮读取缓存。

实例状态包括 `pending`（等待采集）、`available`（正常）、`unavailable`（端点返回 404）、`failed`（请求或响应校验失败）、`stale`（超过两个周期没有新快照）和 `excluded`（地址超出信任范围）。

## 调度、存储和降级

采集独立于注册和心跳。单轮最多 10 个并发，错开请求启动时间。单次超时 1 秒，响应上限 4 KiB。上一轮仍在运行时跳过新一轮。采集失败保留最近一次成功的指标并显示失败状态。

配置 `RegistryRedisUrl` 后，只有 Redis 采集租约的当前持有者能更新快照。快照键是 `<RegistryRedisKeyPrefix>:{service-monitor}:latest`，租约键是 `<RegistryRedisKeyPrefix>:{service-monitor}:lease`。TTL 取三个采集周期和 60 秒中的较大值，租约失效后其他副本可接手。

Redis 未配置或失联时，每个副本保留本机最近一次结果并独立采集。Redis 恢复后重新协调租约并共享快照。第一版只保留最新采样。
