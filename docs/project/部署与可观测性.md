# 部署与可观测性

## 启动与存储

首先构建相邻的 NestCloud-Sdk，再安装 NestCloud。按照[启动说明](../../README.md)准备 PostgreSQL 与会话配置，启动注册中心和配置中心后，再启动接入的业务服务。

配置中心在 PostgreSQL 的 `sys_config_file` 表中维护草稿和发布快照。已启用配置中心的客户端在启动时拉取发布版本。远程配置不可用时，客户端使用校验通过的本地配置，运行中刷新失败时继续使用上一个有效快照。

`RegistryRedisUrl` 决定注册存储方式。配置 Redis 时，多个 NestCloud 实例可共享注册记录。留空时，各进程使用各自的内存记录。独立的 `SessionRedisUrl` 控制登录会话存储。

## 数据库脚本

| 用途                 | 脚本                                                                                   | 执行位置                                                       |
| -------------------- | -------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| 配置文件和发布快照   | [sql/init.sql](../../sql/init.sql)                                                     | NestCloud 的配置库                                             |
| SDK 的写请求幂等记录 | [sql/sdk/add-rpc-idempotency-record.sql](../../sql/sdk/add-rpc-idempotency-record.sql) | 启用幂等的接收方业务库，当前为 SolaCloud 的 middleware-service |

`DatabaseIdempotencyService` 使用接收方的数据库事务写入业务数据和 `rpc_idempotency_record`。新建业务库或升级已有业务库时，都应在启用写重试前执行对应 SDK 脚本。多个接收方共用同一数据库和 schema 时可共用该表。

## 管理控制台构建

`console/main.ts` 是管理控制台入口，`console/config/` 和 `console/registry/` 分别维护配置页和注册页。浏览器通过 HTML 中的 `js/main.js` 加载编译后的 ES 模块。开发时运行 `pnpm start:dev`。部署前安装包含开发依赖的锁定版本并运行 `pnpm build`，将整个 `public/` 与服务端的 `dist/` 一起交付。以项目根目录为工作目录运行 `pnpm start:prod`，以便 SDK 扫描后端控制器。

`public/vendor/` 由控制台构建生成。Bootstrap 的样式和 bundle，以及 Monaco 的 AMD loader、编辑器、字体、语言模块和 Worker，均通过同一服务的静态路由提供。更新依赖后重新构建即可更新部署资源；运行中的浏览器无需访问 CDN。

## 注册地址升级与回退

SolaCloud 的三个业务服务在 `NodeEnv=production` 时向 `RegistryUrl` 注册并发送心跳。需要通过 HTTPS 网关访问提供方时，在该服务设置 `ServiceBaseUrl`（例如 `https://middleware.example.com/api`），并确认调用方能解析网关域名且信任其证书。省略该项时，客户端根据 `ServiceHost`、`Port` 和 `GlobalPrefix` 广播 HTTP 地址。

先升级注册中心与消费端，再启用提供方的 HTTPS 广播地址。仍使用旧 SDK 的消费端通过 `host` 和 `port` 访问，升级期间应保持该地址可达。回退时移除提供方的 `ServiceBaseUrl` 并重启以重新注册，消费端下次同步即可获取新的地址。

## 日志与链路

SDK 通过 winston 输出日志。控制台级别由配置决定，非生产环境默认启用控制台输出。HTTP 入口按 W3C 约定传递 OpenTelemetry 上下文，可根据响应头 `x-trace-id` 关联各服务日志。客户端以独立 span 记录每次重试。生产部署可以接入已有的 tracer provider，基础服务无需额外运行采集器。[SDK 调用策略](../../../NestCloud-Sdk/docs/http/链路传递与重试.md)
